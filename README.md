## Overview

FigureInk is a portable agent Skill and deterministic Matplotlib renderer for
creating hand-lettered scientific charts from verified structured data. It can
be used with Claude Code, Codex, Kimi Code, OpenCode, and other coding agents that
can read local instruction files and execute Python. It is designed for academic
figures that require a distinctive visual style without compromising numerical
accuracy, editability, or reproducibility.

The renderer reads a JSON specification, validates the data and visual settings,
and exports publication-oriented vector and raster files. Bars, lines, missing
segments, uncertainty intervals, labels, and highlighted points remain directly
connected to values declared in the source specification.

## Key features

| Feature | Description |
|---|---|
| **Data-faithful rendering** | Visual marks are generated directly from declared values. The renderer does not infer missing measurements or rescale percentages. |
| **Agent-portable package** | The core workflow uses Markdown instructions, JSON specifications, and Python scripts rather than a proprietary agent API. |
| **Supported chart families** | Horizontal bar charts, grouped bar charts, line charts, and multi-panel compositions. |
| **Single-hue palette system** | Twelve curated palette families provide semantic roles at different lightness and saturation levels within the same hue family. |
| **Publication-oriented output** | Each render can produce editable PDF and SVG files, a 300-dpi PNG, and a grayscale preview. |
| **Preflight validation** | Invalid lengths, bounds, colors, uncertainty values, references, axes, and style options are rejected before export. |
| **Reproducibility records** | The output manifest records source and renderer hashes, runtime versions, palette selection, dimensions, and artifact hashes. |
| **Portable typography** | Comic Neue Regular and Bold are bundled under the SIL Open Font License. |

## Synthetic showcase

The figure shown above is generated from entirely synthetic data. It does not
contain manuscript results, benchmark measurements, or data from a real
experiment. The example includes:

- 100 simulated paper-plane flight outcomes;
- repeated simulated landing trials under three conditions; and
- two synthetic distance trajectories with an uncertainty band.

The generator uses the fixed random seed `20260804`, so the same command produces
the same JSON specification:

```bash
python3 showcase/generate_synthetic_showcase.py
```

To generate a different synthetic example, provide another seed:

```bash
python3 showcase/generate_synthetic_showcase.py --seed 42
```

The showcase uses one blue palette across all three panels. Its plotted lines use
straight geometry (`"sketch": "none"`).

## Palette system

![Twelve single-hue palette families](showcase/palettes/plot-handdrawn-paper-charts-palettes.png)

Each palette defines six semantic roles: `primary`, `secondary`, `tertiary`,
`accent`, `neutral`, and `pale`. The roles differ in lightness and saturation but
remain within one color family. Marker shapes, line styles, and hatches can provide
additional separation when a figure must remain interpretable in grayscale.

| Palette | Intended use |
|---|---|
| `ocean-blue` | General scientific figures and method comparisons |
| `ink-indigo` | Formal result summaries |
| `sage-green` | Human evaluation and qualitative analysis |
| `forest-green` | Systems, efficiency, and robustness results |
| `lagoon-teal` | General comparisons and balanced multi-panel figures |
| `plum-purple` | Multimodal and cross-domain results |
| `lavender` | Supporting or exploratory analysis |
| `dusty-rose` | Preference studies and taxonomies |
| `sunset-orange` | Motivation and problem-analysis figures |
| `terracotta` | Error and failure analysis |
| `ochre-gold` | Highlights and efficiency comparisons |
| `graphite` | Monochrome and print-oriented output |

For most figures, select one palette and use its semantic roles consistently across
all panels.

## Agent compatibility

FigureInk is organized as a self-contained instruction package:

- `SKILL.md` defines the workflow and quality requirements;
- `scripts/render_chart.py` provides deterministic validation and rendering;
- `references/` contains the chart schema, color system, and publication checks;
- `assets/` contains examples and portable font resources; and
- `agents/openai.yaml` provides optional Codex interface metadata but is not
  required by the renderer or the core instructions.

The package can therefore be used by Claude Code, Codex, Kimi Code, OpenCode, or
another agent with equivalent local-file and Python execution capabilities. The
exact registration directory and command syntax depend on the selected agent.

## Installation

### Ask your coding agent to install it

Open this repository with your coding agent, or provide the GitHub URL in a task,
and use the following request:

```text
Install the open-source FigureInk agent Skill from
https://github.com/yzbcs/FigureInk. Use
skill/plot-handdrawn-paper-charts/SKILL.md as the primary instruction file.
Install the Python dependencies, register or link the Skill according to your
agent's local convention, validate the bundled specifications, and run a smoke
render to confirm the installation.
```

### Manual installation

```bash
git clone https://github.com/yzbcs/FigureInk.git
cd FigureInk

python3 -m pip install -r skill/plot-handdrawn-paper-charts/requirements.txt

# Optional: copy the package into the skills directory used by your agent.
AGENT_SKILLS_DIR="/absolute/path/to/your-agent/skills"
mkdir -p "$AGENT_SKILLS_DIR"
cp -R skill/plot-handdrawn-paper-charts "$AGENT_SKILLS_DIR/"
```

If an agent does not provide a dedicated skills directory, keep the repository in
place and instruct the agent to read
`skill/plot-handdrawn-paper-charts/SKILL.md` before running the renderer.

## Usage

### Use the Skill with a coding agent

Generated figures can use flexible panel compositions and are not limited to
1×3, 2×2, or 1×2 layouts. Describe the intended structure and visual requirements
clearly in the prompt.

```text
Read skill/plot-handdrawn-paper-charts/SKILL.md and use FigureInk to convert
these verified results into a double-column scientific line chart or bar chart.
Use one print-safe color family, straight geometry, a confidence band, a
grayscale check, and a reproducibility manifest.
```

### Run the renderer directly

```bash
SKILL_DIR="$PWD/skill/plot-handdrawn-paper-charts"
SPEC="$SKILL_DIR/assets/example_showcase.json"

# Validate the specification without creating output files.
python3 "$SKILL_DIR/scripts/render_chart.py" \
  --spec "$SPEC" \
  --validate-only

# Render the complete output bundle.
python3 "$SKILL_DIR/scripts/render_chart.py" \
  --spec "$SPEC" \
  --output-dir "$PWD/rendered"

# List the available palettes.
python3 "$SKILL_DIR/scripts/render_chart.py" --list-palettes
```

## Specification example

```json
{
  "data_status": "synthetic tutorial fixture",
  "figure": {
    "stem": "paper_plane_range",
    "size": "single-column",
    "palette": "ink-indigo",
    "sketch": "none",
    "dpi": 300
  },
  "panels": [
    {
      "type": "line",
      "x": [1, 2, 3, 4],
      "x_label": "Fold-tuning round",
      "y_label": "Flight range (m)",
      "series": [
        {
          "name": "Dart",
          "values": [3.2, 3.6, 4.1, 4.5],
          "color_role": "neutral"
        },
        {
          "name": "Loopwing",
          "values": [3.1, 3.9, 4.8, 5.6],
          "color_role": "primary"
        }
      ]
    }
  ]
}
```

Use JSON `null` to represent a genuine missing segment in a line series. The
renderer preserves the gap rather than interpolating or inventing a value.

## Output bundle

For a figure with the stem `paper_plane_range`, a standard render produces:

```text
paper_plane_range.pdf
paper_plane_range.svg
paper_plane_range.png
paper_plane_range.gray.png
paper_plane_range.source.json
paper_plane_range.manifest.json
```

The PDF and SVG files are intended for manuscript editing and submission. The PNG
is intended for visual review or raster-only workflows. The grayscale PNG supports
print-readability checks. The resolved source JSON and manifest provide a record of
the data, configuration, runtime, and generated artifacts.

## Validation and reproducibility

Before writing any output, the renderer checks that:

- category and series lengths are consistent;
- error magnitudes are non-negative;
- lower and upper bounds are ordered and contain finite estimates;
- highlights reference existing, non-null data points;
- colors and palette roles are valid;
- axis limits, ticks, labels, dimensions, and DPI are coherent; and
- requested style values are supported.

Exports are written to a staging directory, reopened, checked, hashed, and then
moved into the requested output directory as one bundle. A failed validation does
not create a partial output bundle. On the same recorded runtime stack, repeated
renders are byte-identical.

## Style guidance

- Use `"sketch": "none"` for straight chart geometry and small camera-ready figures.
- Use `"sketch": "subtle"` when a restrained hand-drawn path effect is appropriate.
- Reserve `"sketch": "rough"` for posters or explicitly informal material.
- Use one palette family per figure unless color has an explicit cross-family meaning.
- Keep semantic color roles consistent across panels.
- Combine color with markers, line styles, or hatches when grayscale readability is required.
- Place value labels outside filled bars.
- Treat PDF or SVG as the source of record for manuscript figures.

## Continuous integration

The GitHub Actions workflow runs on every push and pull request. It checks Python
3.9 and 3.12, compiles the renderer, validates both bundled specifications, and
performs a real smoke render. The workflow only verifies the repository; it does
not publish releases or modify source files.
